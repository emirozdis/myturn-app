# MyTurn Mobile App

The MyTurn mobile app is built with Expo, React Native, TypeScript, and Expo Router. It includes daily video capture and playback, friend groups, profiles, streaks, reactions, subscriptions, notifications, and home-screen widgets.

This is an independent private repository, linked into the [MyTurn parent repository](https://github.com/emirozdis/myturn) as `myturn-app/`. Its backend lives in [myturn-backend](https://github.com/emirozdis/myturn-backend).

## Local setup

Use a recent Node.js version compatible with the Expo version in `package.json`, npm, and the platform tools required by your target: Xcode for iOS or Android Studio and JDK 17 for Android.

```sh
npm ci
cp env.example .env.development
```

Edit `.env.development` with your local API URL and development service values. The default `http://localhost:3000` works with the iOS simulator; the app maps localhost to `10.0.2.2` for the Android emulator. Use your computer's reachable LAN address on a physical device.

Obtain `GoogleService-Info.plist` and `google-services.json` for the configured Firebase project and place them in this folder. They are ignored by Git, along with signing credentials and environment files. Native Firebase modules and widgets require a development build.

```sh
npm run ios
# Or:
npm run android
```

After installing a development build, `npm start` runs the development server. The native folders are generated by Expo; persistent native changes belong in `app.config.js`, `app.json`, or `plugins/`.

## Environments and builds

The npm scripts select the environment. Do not put `APP_ENV`, `EXPO_PUBLIC_APP_ENV`, or `LOAD_LOCAL_ENV` in local environment files: `app.config.js` rejects them.

- Development commands load `.env.development`.
- Local production commands load `.env.production`; create it from `env.example`, then supply production values and an HTTPS API URL.
- Local preview commands use `.env.production` plus the registered App Check debug token from `.env.development`. Preview uses production services.
- Cloud builds use the profiles in `eas.json` and the appropriate EAS environment configuration. The development profile currently enables local-file loading, so configure its build environment accordingly.

```sh
npm run build:development
npm run build:preview
npm run build:production
```

These commands invoke EAS builds and require access to the project's Expo account and platform credentials. Use the existing `development`, `preview`, or `production` build profiles. The `build:testflight` scripts currently refer to a build profile absent from `eas.json`; use the production build profile for an App Store build. The separate `testflight` submission profile exists for `npm run submit:testflight`.

## Source layout

| Folder | Contents |
| --- | --- |
| `app/` | Routes and screen entry points |
| `src/components/` | Product UI and shared controls |
| `src/lib/` | API, authentication, media, localization, and service integrations |
| `src/store/` | Zustand state stores |
| `widgets/` | Home-screen widget views |
| `plugins/` | Expo native configuration plugins |
| `assets/` | Images, icons, and fonts |

For a TypeScript check, run `npx tsc --noEmit`. Store disclosure notes are in [docs/STORE_PRIVACY_DECLARATIONS.md](docs/STORE_PRIVACY_DECLARATIONS.md).

Commit and push app changes here, then update the `myturn-app` submodule reference in the parent repository.
